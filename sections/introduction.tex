Recent studies on AI coding agents have proven the efficacy of using Large Language Models (LLMs) to handle coding tasks such as code generation and debugging. To apply LLMs in daily software engineering scenarios, both industry and academia have proposed many agentic frameworks. Industry-proprietary examples include Google's Colab AI \cite{google_2025_colab_ai_first}, Claude Code \cite{anthropic_2025_claude_code_ga}, and Cursor Agent \cite{cursor_2025_agent_cli}. There is a continuous and rapid growth of user bases for these frameworks, reflecting their perceived utility in real-world software engineering tasks. Besides the proprietary frameworks, there are also many open-source implementations from both academia and industry, including Gemini Cli \cite{mullen_salva_2025_gemini_cli}, SWE-Agent \cite{yang2024sweagent}, AutoCodeRover \cite{zhang2024autocoderover}, and Agentless \cite{xia2024agentlessdemystifyingllmbasedsoftware}. These frameworks enable existing LLMs to achieve high task success rates when prompted with clear instructions and sufficient code context.

A common characteristic of these agents is that they issue many requests to the LLM during a single task. Each request often carries a long prompt: repository structure information, multiple code snippets retrieved as context, system instructions, and the issue description. The repeated and overlapping nature of this content across requests means a serving system that re-processes every prompt from scratch wastes a large fraction of compute on tokens it has already seen. This redundancy directly translates to high time-to-first-token (TTFT) and high cumulative cost per task. The latency cost is particularly important because agentic workflows are interactive: a user typically waits for the agent's output, and slow generation degrades developer productivity in a way that aggregates across many sessions.

The standard solution to this redundancy is KV cache reuse, where the serving engine stores intermediate attention states from previous requests and reuses them when the same tokens appear again. Modern serving engines such as vLLM \cite{kwon2023vllm} and SGLang \cite{zheng2024sglangefficientexecutionstructured} implement prefix caching, which reuses cached KV states only when prompts share an exact prefix from the start. In an agentic setting, however, calls often share partial contexts that appear after some unique tokens, leading to low cache hit rates under prefix-only matching. CacheBlend \cite{yao2025cacheblendfastlargelanguage} addresses this by enabling \emph{position-independent} KV cache reuse: the prompt is treated as a sequence of chunks, each chunk is matched against the cache independently, and a small subset of cross-attention-sensitive tokens are recomputed to restore correctness. The original CacheBlend paper demonstrates 2--3$\times$ TTFT reduction and 3--5$\times$ throughput improvement on multi-round question-answering workloads.

CacheBlend's original evaluations, however, did not cover the workload characteristics of code agents. Agentic prompts are longer, often contain code blocks that are reordered or partially substituted across successive requests, and arrive at higher concurrency. Two specific properties of the reference implementation (LMCache) limit its applicability in this regime: cache lookup requires contiguous prefix alignment, so reusable chunks that follow a differing prefix are missed; and the storage backend allocates one memory object at a time under a global lock, which serializes large requests with many chunks. The per-step retrieve path is also opaque under existing instrumentation, making it difficult to diagnose where time is spent when speedup is lower than expected.

This thesis presents a set of enhancements to LMCache that address these limitations, together with an end-to-end evaluation under realistic code-agent workloads. The core technical contributions are on the backend serving system:

\begin{itemize}
    \item \textbf{Position correction for non-contiguous reuse}: the upstream implementation defines a runtime path that is supposed to correct rotary positional embeddings when a cached chunk is reused at a new position, but the metadata field it depends on is not actually populated. We add the missing \texttt{old\_positions} field to the memory object metadata along with its serialization handlers, completing the path so that content-matched chunks can be reused at any position in subsequent prompts.
    \item \textbf{Enhanced memory allocation and locking}: a batched varied-shape allocator reduces lock contention proportionally to the number of cache chunks per request, and a bounded eviction loop prevents deadlocks when all cache entries are pinned by concurrent lookups.
    \item \textbf{Per-request profiling infrastructure}: a thread-local profiler instruments the cache engine, storage backend, and GPU connector along the critical path, emitting structured per-operation and per-phase timing records for post-hoc analysis.
\end{itemize}

To evaluate these enhancements under realistic agentic traffic, the system is wrapped in an end-to-end pipeline that includes a context retrieval frontend. Producing a realistic agentic workload requires a method for assembling the per-request prompts that a real code agent would issue, including repository structure, relevant code snippets, and an issue description. We use RepoGraph \cite{ouyang2025repographenhancingaisoftware} combined with the Agentless procedural framework \cite{xia2024agentlessdemystifyingllmbasedsoftware} as a concrete instantiation of the frontend. The frontend is treated as a pluggable component: any context retrieval module that produces structured prompts with explicit chunk boundaries can be substituted for it without affecting the backend design. Our frontend evaluation primarily serves to verify that the backend cache reuse does not degrade output quality and that the integrated system performs consistently across multiple LLM backends.

The remainder of this thesis is organized as follows. Chapter~\ref{cha:background} provides background on KV cache reuse and CacheBlend, then on context retrieval and RepoGraph, and motivates an integrated system that supports realistic backend evaluation. Chapter~\ref{cha:design} presents the system design, with emphasis on the backend cache engine enhancements that constitute our core contribution, followed by the frontend integration details required to complete the end-to-end pipeline. Chapter~\ref{cha:eval} reports the latency evaluation of the enhanced backend under agentic workloads, followed by the supporting performance evaluation of the context retrieval frontend across multiple LLM backends.
