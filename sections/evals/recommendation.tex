\section{Case Study: Blend or Prefix?}
\label{sec:recommendation}

The results above show that neither mechanism is better for every request. Blending serves localization hits about four times faster than prefix caching. For exact repeats the order is reversed: prefix caching simply loads the stored state of the earlier prompt, while blending also recomputes part of it, as it does for every hit, even though nothing in the prompt has moved. Applied to every request, the two come out even: at 5\% of the working set, the mean TTFT over the whole trace is 2.10\,s under either mechanism (Table~\ref{tab:routing}). This raises a practical question: can each request be sent to the mechanism that serves it best?

\subsection{Routing by Reuse Type}
\label{sec:rec_controller}

The two kinds of reuse are easy to tell apart before a request is served. An exact repeat sends a prompt the cache has already seen in full. In the agent we study, every sampled repair request repeats the greedy repair prompt sent just before it, and the agent knows this when it sends the request. A router can therefore send exact repeats to prefix caching and every other request to blending. The signal does not have to come from the agent: the serving engine can also recognize an exact repeat by comparing a hash of the whole prompt against the prompts it has already stored.

Table~\ref{tab:routing} compares this routing policy with serving every request through a single mechanism, at 5\% and 2\% of the working set. Routing is faster than either mechanism alone at both sizes: 3.3\% faster than the better single mechanism at 5\% of the working set, and 2.7\% faster at 2\%. It also comes within 0.4\% of the best possible per-request choice, which serves each request with whichever mechanism was faster for it. Nearly all of the benefit of choosing per request is captured by a rule that only needs to know whether the prompt is an exact repeat.

\subsection{Measured Routing}
\label{sec:rec_measured}

The routed results above combine per-request measurements from the prefix-caching and blending runs. A routed implementation serves both kinds of request in the same run, so a single cache holds the state of both mechanisms at once and their entries compete for the same capacity.
