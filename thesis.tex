\begin{abstract}
Recent advances in Large Language Models (LLMs) have enabled the development of coding agents that can autonomously perform tasks such as code generation, debugging, patch validation, etc. Industry-proprietary systems (e.g., Colab AI, Claude Code, Cursor Agent) and open-source frameworks (e.g., Gemini Cli, SWE-Agent, AutoCodeRover, Agentless) have demonstrated both practicality and popularity in real-world software engineering workflows. These agents send their language model long prompts that overlap heavily from one request to the next, which makes reusing the attention state of earlier requests, the KV cache, a natural way to cut latency. Prefix caching, the standard technique, reuses only content that matches from the very start of a prompt. CacheBlend relaxes this: it reuses cached chunks wherever they appear and recomputes a small fraction of tokens to repair the result. This thesis is a case study of what that buys a real coding agent. We serve RepoGraph + Agentless with vLLM and LMCache, record the requests the agent sends while working on SWE-bench issues, and replay the trace under prefix caching and under CacheBlend at five cache sizes, from 40\,GiB down to 1\% of the trace's working set. Most of the trace's reuse comes from exact repeats of earlier prompts, which both mechanisms capture. Blending adds up to 3.9 percentage points of reused prompt tokens, all of it in the localization stage, where requests share repository context that follows their own issue text. Requests that blending hits run a median of 4.3$\times$ faster than under prefix caching, a gain capped by the fraction of tokens blending recomputes. Cache size changes how many requests hit, not what a hit is worth: blending's hits are reused long after they are stored, so they are the first to be evicted, and a request that loses its hit falls back to prefix-caching speed. Applied to every request, blending is no faster than prefix caching on this trace, because it also recomputes part of every exact repeat. Sending exact repeats to prefix caching and all other requests to blending is faster than either alone and close to choosing the better mechanism for each request. The findings argue that position-independent reuse belongs in a coding agent's serving stack, applied by the kind of reuse a request carries rather than by default.
\end{abstract}
