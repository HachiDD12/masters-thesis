\begin{abstract}
Recent advances in Large Language Models (LLMs) have enabled the development of coding agents that can autonomously perform tasks such as code generation, debugging, patch validation, etc. Industry-proprietary systems (e.g., Colab AI, Claude Code, Cursor Agent) and open-source frameworks (e.g., Gemini Cli, SWE-Agent, AutoCodeRover, Agentless) have demonstrated both practicality and popularity in real-world software engineering workflows. These agents send long prompts to the LLM, and consecutive prompts often share much of their content. Reusing the KV cache computed for earlier requests is therefore a natural way to reduce latency. The standard technique, prefix caching, can only reuse content that matches from the beginning of the prompt. CacheBlend removes this restriction by reusing cached chunks at any position in the prompt and recomputing a small fraction of tokens to repair the reused KV cache. In this thesis, we present a case study of how much CacheBlend helps a real coding agent. We serve RepoGraph + Agentless with vLLM and LMCache, record the requests the agent sends while solving SWE-bench issues, and replay this trace under prefix caching and under CacheBlend with five cache sizes, ranging from 1\% of the trace's working set up to 40\,GiB. We find that most of the reuse in the trace comes from exact repeats of earlier prompts, which both mechanisms capture. Blending reuses up to 3.9 percentage points more prompt tokens than prefix caching, all of it in the localization stage, where requests share repository context that comes after their own issue text. Requests that blending hits run a median of 4.3$\times$ faster than under prefix caching, and this speedup is bounded by the fraction of tokens that blending recomputes. A smaller cache reduces the number of requests that hit, but has little effect on the speedup of each hit. Since blending's hits are reused long after they are stored, they are evicted first, and a request that loses its hit runs at the same speed as under prefix caching. When applied to every request, blending is no faster than prefix caching on this trace, because it also recomputes part of every exact repeat. Routing exact repeats to prefix caching and all other requests to blending is faster than using either mechanism alone, and comes close to choosing the better mechanism for each request. These results suggest that position-independent reuse is useful for serving coding agents, but it should be applied based on the type of reuse in each request instead of to every request.
\end{abstract}
